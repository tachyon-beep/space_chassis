## 6. Architecture decisions the first tranche must settle

**One executive, distinct windows.** The vehicle owns arbitration needed to make conflicting inputs deterministic and safe. It must not supply the fleet's mission dispatcher, rank table or strategic task allocation. Stamp intake/order service-side, retain the observed order for replay, and test both contention and starvation. Live asynchronous arrival is not inherently deterministic; replay determinism means replaying the recorded accepted input trace. Avoid interpreting a lexical technical tie-break as experimental leadership; counterbalance roster identities in trials.

**One committed world.** Checkpoint state, numerical residuals, delay buffers, event/fault/RNG lineage, mission phase/clock, safety dwell, per-principal ceilings, arm tokens and input/effect journal cursor together. Atomic writes per file are insufficient if files describe different ticks. Specify write-ahead/commit/recovery semantics and test process death and failed writes at each boundary. No agent-facing mirror may restore authority. Never promise exactly-once submission: the frozen contract deliberately clears before acting and permits loss of the remainder of a claimed batch on a crash. Preserve at-most-once intake and record losses/uncertainty. Committed effects must survive; unreconstructable effects invalidate the trial rather than producing an invented outcome.

**Frozen window compatibility.** Keep external command-line transport and result shape. Internal typed commands and private lifecycle journal can strengthen it. Preserve the one-result-file contract; do not emit extra public files per lifecycle stage without a reviewed compatibility decision. The contract lists window `pending.json` as vehicle-to-vehicle storage: settle a permissions/mount design that retains the path while protecting its content, or explicitly decide a safe non-authoritative projection and where actual state resides. Do not silently remove the path or trust agent-writable pending data. Agents may clean their output under the contract; a separate protected operator journal must preserve the acceptance record.

**Time with consequences.** Recommend a fixed physical timestep and integer tick/effect times; distinguish mission time, sample time, publication time, receipt time and wall UTC. Initial agent trials should use wall-real-time mission progression so thinking has a cost; faster scripted replay is a separate mode. Define overload, pause and downtime before implementation. Recommended starting policy is an explicit operator pause/invalidity event on unrecoverable scheduling lag, and restore the last coherent committed tick after a process crash with downtime recorded; never silently stretch time or integrate a guessed interval. John must accept the research consequence of pauses. Preserve the full 50 Hz and replay targets unless he explicitly changes them.

**Evidence versus truth.** Operator-side private traces may see truth for validation. Fleet output must pass a one-way instrument/perception layer. Public model laws can be a deliberate affordance; private initial/fault state and seeds cannot leak through code images, checkpoints, debug errors or metadata. A helper that converts keys and units is only the beginning. Crew are embodied observation/action resources; software agents are ground/controller programs with identical general telemetry access, not assigned stations or roleplay characters.

The first episode should be **quiet-coast power/cooling scheduling**, with no injected fault. Select a bounded mission interval only after F establishes feasible initial margins and task loads. The candidate task is to deliver a declared amount of useful work/data by a contact deadline while keeping power, heat and cabin/consumable margins inside accepted bounds. This is a proposed tasking, not an existing implemented mission objective. Before commissioning the episode, select a supported productive activity and identify its command → physical operation → measurable completion path, or declare the need for an additional task model. For stored-data delivery, the closure includes data quantity/production, recorder capacity, transfer/link availability, transmission draw/heat and a received-data completion measure; the current recorder capacity is unset (`domains/comms/components.yaml:174`). Prefer an existing applicable activity over adding artificial busywork. If no evidenced activity fits, return a blocked episode choice and alternatives to John. The two successful policies below are feasibility hypotheses to prove, never reasons to tune unsupported physics. Any prescribed contact or environmental boundary must be explicit; do not imply a validated orbit merely because a schedule exists.

The physical loop to prove is: task load changes electrical demand and energy/consumable use; dissipated heat accumulates; cooling consumes capacity and may power-load the source; source/protection limits constrain task completion; measurements arrive with declared delay. More cooling cannot be assumed free, and silence cannot freeze depletion. This feedback gives agents reasons to build a shared trend view, schedule, commitment log or watchdog. Those artifacts may also spread stale beliefs or become a single point of failure—useful experimental outcomes, not flaws to remove by assigning roles in advance.
