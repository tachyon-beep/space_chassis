# reconciliation/

The pass `simulator-design.md` §13 calls for: every subsystem spec against apollo, every
spec against every other, and the result written down as decisions rather than rediscovered
per conflict. `integration/README.md` planned one file per domain; this is that plan with a
better factoring, because the expensive disagreements are not per-domain — they are about
names, numbers and codes that all thirteen documents share.

| File | What it is |
|---|---|
| `README.md` | This. Method, the provenance vocabulary, what each artifact is for. |
| `01-conflict-register.md` | Every number, unit, channel and verb where two sources disagree. One disposition each, with the reason. |
| `02-canonical-vocabulary.md` | The names, lifecycle chains, code unions and scales the dictionary will actually key on. |

Sources reviewed: `../corpus-review.md` (what the thirteen documents contain and where they
fail), `../review-findings.md` (the design's own review), `../../apollo_diode.md` (ground
truth), and the eleven subsystem specs.

## Method

**Four provenance classes, on every value that matters.**

| Class | Meaning |
|---|---|
| `apollo` | Anchored to a claim or channel in `apollo_diode.md`. Cite the line. |
| `derived` | Computed from other values in the config. State the relation, so the linter can re-derive it and disagree. |
| `chosen` | Picked to make the simulation run. State the reason; a `chosen` value with no reason is a bug. |
| `UNCONFIGURED` | Needed and unset. The linter fails the build and **names what wants it**. |

The last class is the important one. `thermal_diode.md:29` states the rule for its own
domain — no threshold may "silently default to an invented 'typical spacecraft' value" — and
`simulator-design.md:146-150` generalises it: *a value that is needed and unset fails the
build, loudly, naming what wants it.* So `UNCONFIGURED` is not a placeholder that resolves to
a plausible number; it is a build failure with a message. `coupling.yaml` currently carries 31
of them, which is the honest state of the corpus after extraction.

**The apollo rule is an override, not a tie-break.** `eclss_diode.md:19` and `:734-736`
delete apollo's cabin pressure, CO₂ caution and O₂ supply values deliberately, and
`thermal_diode.md:965` refuses its whole domain on the same principle: a spec that describes
a generic mission-configurable vehicle should not hard-code one vehicle's numbers. This
project wants *this* vehicle, so apollo wins — but that is a decision to override the newer
documents' stated stance, taken once and recorded here, not a rule that resolves ambiguity.
Every such override is listed with the sentence it overrides.

**The dual-diode filter is narrower than the README says.** The transport-security layer is
answered (`electrical_diode.md:442` rates the filesystem pattern "Excellent simulation /
research baseline"). Two things survive the filter and are carried here as decisions:
`communcations_diode.md:102`'s attack on destructive intake's *crash semantics* — a claimed
batch lost with no result file breaks `diode-contract.md:101`'s own "a refusal is a result"
rule — and the same document's argument for a machine-readable result. See D-01 and D-02.

**A verb belongs to the domain that owns the thing it acts on, not the domain that pays for it.**
`set_absorber_path` was written into the consumables domain in round 4 and moved to ECLSS in
round 6: the beds' capacity is a resource — consumed, floored, planned against — but the path is
a routing decision about cabin air. `set_o2_source` stays in consumables for the mirror-image
reason, because *which tank to spend* is a resource decision while *how fast to spend it* is an
atmosphere one. Two verbs, two questions, and a fleet that has to think about which it is asking.

## How a domain lands

Per `simulator-design.md:128-134`, a domain arrives as `domains/<name>/` with five files:
`components`, `points`, `profiles`, `commands`, `fault_policy`. The workflow that keeps this
from becoming eight codebases:

1. Lift the spec's point dictionary into `points`, **renaming every identifier to the canonical
   channel** (`../../apollo_diode.md`'s names; `02-canonical-vocabulary.md` §3). A row whose
   apollo counterpart does not exist is either a real gap in apollo or a fabricated channel;
   decide which and write it down.
2. Lift the command table into `commands`, lowercased to apollo's verb style, with each verb
   declaring `gate` (agent-writable, a preference) or `interlock` (service-owned, not a
   preference). The two must never be the same field — `eclss_diode.md:741`,
   `thermal_diode.md:823-826`.
3. Lift the state machines into `fault_policy` with their thresholds, dwells and hysteresis.
   Every latched state on a declared cycle needs hysteresis, not dwell alone.
4. Run the linter. It reports what the domain now owes the rest of the vehicle — which is how
   the config grows into a whole vehicle instead of eight parallel ones.
