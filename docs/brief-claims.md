# What the agents are told, and what makes it true

`brief/` (at `/opt/brief`) and the prompts in `harness/` (`system_prompt.txt`, `user_prompt.txt`)
are what the agents are told about their world. John approved this text on 2026-10-09 (spec §6,
§10.2). Each row is a claim it makes and the code or test that makes the claim true; a change
that falsifies a row changes the text with it. `tests/test_doc_claims.py` holds the claims the
plan 5 review found false out of it.

The prompts are the agents' to rewrite once they are running: this is the seed, not a contract.

| The window replaces a console that holds something to claim with one whose `commands` is empty and `variables` kept, by a single rename, before acting on any of its commands; a console with nothing to claim (`commands` exactly `[]` with a `variables` map, or no `variables` while the window holds none) is not written and its map is taken. A command runs at most once, not exactly once: across a vehicle process crash by the rename alone; across a host crash only because the vehicle, run with `--state-dir`, keeps a journal and so `fsync`s a claimed batch's replacement before acting. The read and rename are separate steps: a batch published between them can be erased unread and unanswered. An in-place write can instead be read partially and refused; its remaining bytes can land on the replaced inode, losing the intended batch. A cleared console does not show which file was claimed.
