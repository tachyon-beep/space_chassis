### SV025-01 — P2: invalid current-shape models are presented as runtime size witnesses

**Locations:** `tests/test_chassis_bounds.py:142`, `:175`, `:181`; `docs/planning-context/sv025/RECEIPT.md:54–64`, `:94`; `STATUS.md:5`, `:25`. Relevant existing validators/serializer: `services/chassis_replay.py:150`, `:156`, `:209–233`, `:250–251`.

`current_checkpoint()` adds current keys to the generator's synthetic maximal shape, but retains values that the accepted runtime cannot emit as a valid checkpoint:

- `adopted_through == BIG`, yet all 16 pending generations also equal `BIG`; the first pending generation must be `adopted_through + 1`, with contiguous successors and `next_gen` following them.
- Each of the 64 originals claims `BIG` bytes, exceeding both the 256 KiB item limit and the 4 MiB aggregate limit.
- All original/note hashes equal `Z`, while `blobs_live` contains 80 copies of `Z`; `SessionState.to_wire()` emits the sorted **set** union, which here has one entry.
- The inherited frame/checkpoint sequence fields also do not establish a valid checkpoint relation. Encoding at the maximum sequence with `covers_seq` equal to that sequence is not a valid live checkpoint.

**Failure trace:** `current_checkpoint()` → `cp.encode_frame()` → 21,746 bytes → passing size assertion. The encoder's payload schema check does not validate these state invariants. Passing the state through `SessionState.from_wire()` instead immediately rejects the pending generation relation; fixing only that exposes the original-size and live-reference problems. Thus 21,746 is an encoder-model measurement, not the claimed reachable checkpoint witness. Adding serializer keys alone does not establish reachability.

The same qualification is needed for the current DONE model (`test_chassis_bounds.py:167`): it inherits `stored_E = BIG` from the generator. Actual `record_result` stores the bounded result's escaped length (`chassis_session.py:324–335`), at most 32,768 with default caps. Thus the 1,351-byte modeled result with a 1,000-character exception type is also not a valid exact default-payload witness as constructed. The uncapped exception-type concern remains; it needs a legal size witness or an explicit synthetic-model label.

**Bounded correction:** keep the generator reproduction explicitly as arithmetic over its synthetic source payload. For the current checkpoint claim, either construct a valid bounded state and serialize it through the actual `SessionState.to_wire()` path, or withdraw/relabel this row as an unvalidated synthetic upper-shape model and stop counting it as a demonstrated runtime exceedance. A useful replacement can use contiguous pending generations, realistic note/original byte sizes, distinct hashes where a large live set is intended, and legal checkpoint/previous/next-sequence relations. No enormous history needs to be executed merely to model legal 12-digit counters. Recompute the expected size; do not preserve 21,746 as the target.

**Discriminating regression:** require the replacement's state to validate and round-trip through the actual serializer, verify its bounded item/aggregate sizes and frame/checkpoint relations, then assert the measured frame comparison if it still exceeds 19,978. An intentionally inconsistent generation or repeated `blobs_live` model must fail the validity check even though `encode_frame()` accepts its shape. Update RECEIPT and STATUS to the resulting evidence level.

Apply the same valid-default-domain check to each shape retained as a reachable witness, including DONE's bounded result metadata. It is sufficient to distinguish synthetic envelope arithmetic from validated/reachable examples; this review does not require driving every high-counter state or expanding to a broad runtime audit.

### SV025-02 — P2: the turn/originals argument assumes 32 eligible calls at default caps and overstates the aggregate conclusion

**Locations:** `docs/planning-context/sv025/RECEIPT.md:66`, `:74`, `:97`. Source: `services/chassis_envelope.py:164–172`, `:385–397`, `:419–438`; `services/chassis_session.py:291–303`.

For indices 16–31, `index >= caps.calls` selects `not_run_call_limit` before either original-retention branch. The cited invalid-JSON branch is never reached for those calls. Content and reasoning produce originals only when truncated, so a roughly 20 KB total response cannot supply those two 64 KiB-overflow originals either.

**Concrete branch trace:** use 32 distinct invalid argument strings over 512 bytes, valid names, and content/reasoning large enough to truncate. Calls 0–15 can add 16 argument originals; calls 16–31 add none; the two truncated fields add at most two. This construction supplies at most 18 new originals, not 34. It does not establish the receipt's 34 count evictions. Byte-pressure eviction is a different mechanism and must be analyzed separately, including distinct hashes and the retained FIFO.

The subsequent sentence, “So U_r = 103 and U_b(turn) = 3,333,164 are not runtime maxima either,” also does not follow from individual frame/count discrepancies. The canonical sum deliberately combines conservative terms, including mutually exclusive call outcomes and a separately counted notice now reduced from TURN_RESPONSE. Showing that a component differs does not show that a complete reachable unit exceeds the aggregate. This review does **not** assert that either aggregate is valid; their proof remains open.

**Bounded correction:** reconcile the static argument with default admission, original-retention and byte/count eviction rules. Either supply a complete feasible unit and measured/countable aggregate exceeding the claimed bound, or retain the component discrepancies as failed proof premises and mark the aggregate bounds unproved. A refuting aggregate fixture is not required for this package: removing the unsupported conclusion is sufficient. Do not increase injected caps and present that as a default witness.

**Discriminator if retaining a numerical originals witness:** a small pure adoption fixture with default `Caps`, 32 distinct malformed argument strings and separately controlled truncated fields should assert the admission split and original fields. If claiming actual eviction records, drive the existing bounded retention path with a valid prior FIFO and assert the resulting distinct eviction records; distinguish count pressure from byte pressure.
