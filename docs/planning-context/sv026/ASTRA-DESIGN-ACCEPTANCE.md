## Finding closure and approved scope

**SV026-01 — baseline and headers: closed.** DESIGN §§1.1–1.3 now distinguishes the interval origin from later frames. The origin is the newest CHECKPOINT, or the genesis header at seq 1 before any checkpoint. Its physical replay cost remains the separate unresolved `T_origin` term. Every later header is charged, including pre-first-checkpoint rotations and an empty-segment header recreated by `continue_after`. The unchanged C-G2 fixture contains no later rotation header, so its [9,18] positions do not require a golden-value change.

The proposed writer claim list is coherent with existing ordering. A newly opened header becomes claimable only after its write, file fsync and directory fsync succeed. Construction takes the genesis/reuse claim; rotation takes subsequent claims. Reading an already-existing complete header creates no new claim: the selected replay accounts for it instead. During recovery, `extra` is determined before `continue_after` can create a reuse header, so adding the construction claim to the selected replay's work avoids both omission and double counting. The startup initialization must retain the proposed `+=`, not overwrite that claim.

**SV026-02 — read outcomes: closed with the stated partial-I/O limit.** `BlobStore.fetch` reports obtained bytes before hashing, while `get` preserves its existing bytes-or-None behavior. A wrong-hash read charges its actual returned length. `ReadTooLarge.obtained` exposes the existing `limit + 1` probe without another read. Missing/bad-name cases charge zero obtained bytes; other read errors are explicitly unmeasured. Production replay uses the outcome-bearing interface, while planning/witness/scanner reads remain outside the selected suffix counter.

The new `since_unmeasured` field matters: when it is nonzero, `since_bytes` is the measured component, not an exact total of physical I/O. The design preserves that limitation and does not claim that the threshold comparison covers unknown partial reads. The historical valid-result charge difference is correctly separated from discarded read work. Lost-DONE behavior and refusal for other missing replay payloads remain unchanged.

The test oracle uses file frame lengths and independently observed read results, not the new counter or production `obtained` field. Using the fixture file's independently read size to check an over-limit probe is appropriate in these controlled, non-concurrently-mutated temporary roots; it is not a general arbitrary-fault I/O oracle.

**SV026-03 — production callback: closed.** Passing the checkpoint's actual message list to `meta_source(messages)` resolves the early `_meta_fields` use of the empty pre-session list. The two existing zero-argument test callbacks are explicitly identified for arity-only changes. Static search of the reviewed source found the stated production assignments and those two test callbacks. `_meta_fields(messages=None)` retains its later/no-argument use; the install callback already receives the right messages. Extracting the existing `Chassis._open_session` wiring provides a bounded way to exercise the real callback before `self.session` is assigned, without exposing a partly recovered session or involving a provider.

**SV026-04 — finite acceptance coverage: closed subject to the launch corrections below.** The revised plan separates per-unit delta checks from the old startup record offset; includes recovery records in missing/damaged DONE expectations; distinguishes genesis, pre-checkpoint rotation, post-checkpoint threshold crossing and reuse; checks identity coverage rather than demanding a redundant rename; and adds lifetime/reset, post-GC parity, callback and follow-up failure/crash cases. The retained selection is tied to affected behavior rather than ten blanket module runs. The coordinator's statically expanded target manifest should be the launch list.

## Accounting, boundary and GC composition

The lifetime Replay accumulators plus live before/after deltas remain sound. The Session interval resets at CK6, while the Replay lifetime totals do not. Separately claimed live headers add to Session accounting exactly once. Selected startup replay, readable extras and newly committed recovery records are then composed without importing the previous-base `middle` interval, rejected candidates or witnessed verification work. The implementation must keep the legacy reader path and the new fetch path distinct when updating shared `_replay` callers.

The startup threshold check remains after `_finish_case`, inherited extra-record syncs, the correct carrier/RECOVERING retirement order, and durable identity coverage. It must not add a checkpoint to a still-active frozen recovery plan. Per-generation adoption/drop checkpoints preserve the persisted watermarks, pending/foreign state and queue/group guards.

G2 is bounded: only a successful collection ending in GC_DONE can request one follow-up; the follow-up does not collect; the outer invocation returns it immediately, so rotation occurs once at the end. The same `ended` argument is carried within that operation. Refusal and persistence failure do not fall through to the follow-up. This is compatible with optional GC after CK6 and requires no new user-policy choice.

R-D is an honest deferral: new startup/adoption/drop checks do not add rotation points. The design names the next permitted rotation opportunities and the possible extra segment overshoot. A charged header is evaluated at the next closure, preventing tiny-threshold checkpoint/header loops. Acceptance does **not** close the all-boundaries rotation obligation or prove the `MAX_SEGMENT_READ` slack bound. Keep this limitation visible in the implementation receipt.
