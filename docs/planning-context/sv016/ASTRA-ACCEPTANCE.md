## Conditional hardening

**Nonblocking status-semantics clarification (SV016-05):** `responded` is set before `_relay` executes. A concrete fault injection at `_relay` entry, after a provider 200 has settled, can therefore emit no headers and still record `outcome:aborted, status:200, relayed:false`. `_refuse` similarly retains its selected error status. The new tests establish null status for aborts before a response attempt, not proof that a non-null status was emitted. This matches the existing failed-write paths' selected/attempted-status behavior and does not reintroduce the upstream-relay or accounting defect; acceptance remains unchanged. Checkpoint 005's wording “unless a response was already sent” is too strong and should say “unless a response attempt had begun.” If actual header-emission semantics are desired later, they require a separate response-start observation rather than this flag. Consumers must not read non-null `status` as proof of delivery.

- **Parser totality:** label and forwarded-body encoding now fall under the ValueError/RecursionError refusal guard. The near-limit sweep is bounded and the forced-encoder tests exercise fixed refusals. This closes the identified guard gap; it does not establish that a specific natural nesting depth previously failed, nor guarantee recovery from process resource exhaustion. No broad catch swallowing control exceptions was introduced.
- **Retired-ID reuse:** admission now checks both touched rolling indexes while holding the same lock, after pruning. This prevents the concrete same-socket overwrite/prune counterexample without unbounded identity storage. A test verifies refusal while retained and eligibility after expiry. Handler IDs remain process-global boot/counter values, with concurrent uniqueness coverage. Cross-socket/retired identity misuse still depends on the documented never-reuse API precondition; this was not a demonstrated client path.
- **Usage:** the additional `_is_count` check makes invalid known actual values settle unknown without numeric corruption; zero remains valid. Extractor table tests cover bool, negative, float/string, valid fallback pairs, incomplete pairs and absent/malformed usage. Direct invalid-Usage tests cover the arithmetic-sensitive cases. No new valid-usage accounting regression is apparent.
- **Documentation:** FIFO tombstones, omission of zero-delta late entries, the narrowed accounting-only event schema, absent peer metadata, slot/body ordering, and urllib redirect/proxy behavior are explicitly disclosed. The correction does not silently promote any of these into stronger claims.
