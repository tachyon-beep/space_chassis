# Three-stream restructure: one repository, worktrees, two build streams plus governance

As of **2026-10-15**, `tachyon-beep/space_chassis` `aurora-port` @ `d550880`, vehicle gitlink
`8c6f71d`. Asked for by John in the Space Aurora project (2026-10-15): "rather than having multiple
repos, we can just have agents work in worktrees, and we want to restructure the folders per the two
plus one stream approach — vehicle sim, aurora container, governance stream".
**Verify against the tree before trusting any line here.**

## Why

Today the product is split over two repositories joined by a submodule pointer
(`docs/deep_research/vehicle` → `tachyon-beep/space_vehicle`). Every vehicle change is two commits in
two repositories, the chassis pins a SHA it has to "adopt", and the two lines coordinate checkouts,
vehicle clones and `.claude/worktrees/` by hand (`governance/chassis/practice.md`, "Working beside the
vehicle line"). The vehicle is also buried four levels down inside the evidence corpus. One repository
with one folder per stream removes the pointer, and git worktrees give each agent an isolated checkout
of the whole product without a second clone.

## Target layout

```
vehicle/      stream 1: the vehicle sim (was the space_vehicle repository, absorbed with its history)
aurora/       stream 2: the Aurora container world (was the chassis root: harness, recorder, pump,
              services, scripts, containers, contract, brief, live, tests, vendor, docs, Dockerfile,
              compose)
governance/   stream +1: plans, decisions, status, records (unchanged in shape)
docs/         the border both streams cite, owned as before by the vehicle line:
              diode-contract.md and the frozen corpus deep_research/
pyproject.toml, Makefile, README.md, CLAUDE.md, AGENTS.md   the root: one suite, one map
```

`docs/` is not a fourth stream. It stays at the root because both streams cite it by
repository-relative path (`vehicle/*.yaml` names `docs/deep_research/apollo_diode.md` and
`docs/diode-contract.md`), and the corpus is frozen: moving it would mean editing the evidence's
citations.

The Docker build context becomes `aurora/`. The vehicle reaches the vehicle image as a named build
context (`additional_contexts: vehicle_src: ../vehicle`, `COPY --from=vehicle_src`), so the agents' build
context no longer contains `docs/`, `governance/` or the vehicle at all, which is stronger than the
`.dockerignore` rules it replaces.

## How agents use worktrees

One clone per host. Each agent works in its own worktree, on its own branch, inside one stream:

```sh
git worktree add .claude/worktrees/<stream>-<topic> -b <stream>/<topic> aurora-port   # or: make worktree STREAM=vehicle TOPIC=clock-seam
cd .claude/worktrees/<stream>-<topic>
```

- Branch prefix names the stream: `vehicle/…`, `aurora/…`, `governance/…`. A branch touches only its
  stream's folder; a change to `docs/diode-contract.md` is the one sanctioned cross-stream change and
  says so in its title.
- `.claude/worktrees/` is already gitignored. A worktree shares the object store, so there is no
  second vehicle clone, no `--reference` dance and no submodule pointer to stage.
- "Adopting" a vehicle change is now merging a `vehicle/…` branch; the chassis's referee
  (`aurora/tests/test_vehicle_reconciliation.py`) and the vehicle's own suite run in the same `pytest`.
